# Choose a next step

## Read the selection

- `selection: rows`: use only `- [x]` rows in `shortlist.md`. Unticked is a
  rejection, not permission to act because a row scored well.
- `selection: artifact`: use `results.md` as a whole. Do not invent row selection.

For row selection, zero ticks among new or materially changed rows is unresolved
unless the user explicitly rejected them all. Ticks carried from an earlier run
remain valid decisions. Never interpret silence as all or none.

## Gate 4

Offer two to four small possibilities grounded in the actual result, selected
rows, and the user's goal. They are examples, not a fixed menu. Invite another
goal and include “nothing” as a valid answer. Ask only for details needed by the
option the user chooses.

Stop. Ticking selects inputs; it does not select an output.

If the user wants to understand the result or think before choosing, route to
`discuss.md`. The discussion leaves Gate 4 open.

If the answer is `nothing`, update:

```text
status: done
next: <the natural refresh, occasion, decision, or return point>
```

Keep the result available. If the user chooses an output, continue with `make.md`.
