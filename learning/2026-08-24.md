Session: `eu-ai-jobs`. First end-to-end run of the finder engine, sources through
scoring. This file is about the **engine**, not the job search — no listings, no
results, no criteria here.

## Bugs the run exposed

### 1. Silent field mismapping is the dangerous failure

`prefilter.py` normalises unknown feed shapes by trying field aliases in order and
taking the first hit. Lever gives Palantir's location three ways:

```json
"country":       "GB",
"workplaceType": "hybrid",
"categories":    { "location": "London, United Kingdom" }
```

`country` came first in the alias list, so 148 Palantir rows were located at "GB",
which matched no pattern, and **every Palantir row was dropped**. No error, no
warning. The only symptom was a survivor count that looked slightly low, and it was
only caught because the count was exactly zero.

Guessing the shape is still the right approach — the alternative is a parser per
site, which `AGENTS.md` forbids for good reason. What was missing was any way to
*see* the guess. That is now `sessions/tools/probe.py`, which prints every
location-ish field a feed offers and warns when there is more than one.

**Generalises to:** a heuristic that fails loudly is fine; one that fails silently
needs an inspection tool shipped alongside it, not better heuristics.

### 2. The script ate the human's work

`03-run.md` tells you to append `page` source rows to `listings.md` by hand. The
script rewrites `listings.md` wholesale on every run. So the workflow instructed a
step that the tool silently undid — EURAXESS rows were re-extracted twice before
the conflict was obvious.

Fixed: everything below a `## page sources` marker is carried across runs and
excluded from the cache parse.

**Generalises to:** when a workflow says "append by hand", the tool that owns the
file has to know that section exists. Check for this pairing anywhere else it shows up.

### 3. A substring check ate the cache

Cache rows are `| kept | Company | ... |`. The header is
`| kept | company | title | ... |`. Header detection used `"| kept |" in line`,
which is true of every kept row. Result: on the second run, all 333 kept rows were
silently discarded from the cache and the run returned 0 survivors.

**Generalises to:** never detect a header by a substring that also appears in data.
Anchor to the full header line.

### 4. A row marked `ok` that fails every run is a lie

NoFluffJobs serves its whole board as one 162 MB JSON dump. The 25 MB cap rejects
it, correctly — but the row stayed `ok` in `sources.md`, so every run produced the
same failure line forever. `01-sources.md` now says: too large to read in one
request is `blocked`, not `ok`.

**Generalises to:** `status` describes what happens when you fetch it, not whether
the site is any good.

## Design changes made today

| change | why |
|---|---|
| `prefilter.py` → `sessions/tools/` | zero topic-specific logic in it. Per-session copies would have meant fixing the three bugs above five times. |
| regexes → `## prefilter` block in `criteria.md` | they were passed on the command line and lived only in shell history. The run was not reproducible the next day. |
| new `sessions/tools/regex.py` | loads that block. Deliberately does **not** parse criteria prose into patterns — that is judgment, and judgment is banned from the pre-filter. |
| new `sessions/tools/probe.py` | see bug 1. Establishes method *and* shows detected fields, at GATE 2, before a bad guess is baked into a source row. |
| `learning/` | this file. |

## What was considered and deliberately not built

- **A generic "thing" abstraction to make workflows non-job-specific.** The rules in
  `AGENTS.md` are already topic-neutral; only the *examples* are job-flavoured, and
  concrete examples are easier to follow than abstract ones. Nothing was changed.
- **Per-domain field alias maps.** The alias list is flat and a tender session can
  append `deadline` and `buyer` to it. An abstraction over a list of strings is not
  worth its own concept.
- **Expiry / closing dates.** This is the one real gap for tenders and grants, where
  the deadline is the entire point. Jobs do not have one, so nothing models it. Left
  unbuilt on purpose — it will be designed correctly in ten minutes with a real
  tender portal on screen, and incorrectly in an hour in the abstract.

## Open, for whoever runs the next session

- **Dedupe key is company + title.** Mistral's London role arrived twice, as
  `Mistral` and `Mistral.ai`, and counted as two companies. Any source that reports a
  company name differently from another source will leak a duplicate.
- **HN "Who is Hiring" cannot be a `feed`.** The Algolia API returns story text, not
  postings. It produced exactly one junk row. It is a read-by-hand source.
- **Two `page` sources render client-side past the first paint** — LinkedIn guest
  search and JustJoin.it. Both are currently `page` in `sources.md` and yield nothing
  from a plain read. They are closer to `blocked` than the row admits.
- **EURAXESS `keys=` appears not to filter.** A search for "artificial intelligence"
  returned a French 3D-animation posting. Four relevant rows in forty. If the research
  branch of a session matters, that parameter needs a proper look.
